# Markdown 日期自动同步

直接运行 `hexo g`（或 `hexo generate`、`npm run build`），生成前会使用文件系统的修改时间自动维护源 Markdown 元数据，无需先执行 `hexo clean`。

| 源文件的日期字段 | 自动操作 |
| --- | --- |
| `date`、`updated` 都缺失或为空 | 补写 `date` |
| 已有 `date`，文件修改时间晚于现有日期 | 保留发布日期 `date`，补写或更新 `updated` |
| 旧文章只有 `updated` | 继续更新 `updated`，保留原有结构 |
| 文件修改时间没有晚于现有日期，或仍在同一秒内 | 不改写日期 |

例：文件于北京时间 2026 年 10 月 9 日 15:30 修改，写入 `updated: '2026-10-09T15:30:00+08:00'`。时间取文件修改时间，精确到秒；不使用运行命令的时间。已有未注明时区的日期按北京时间解释。

适用范围为 `source/` 下带 YAML 元数据和标题的 Markdown，包含 `_posts/`、独立目录文章和 `index.md`。第三方 `source/lib/`、数据目录 `_data/`、`test-raw-html/`、隐藏文件及符号链接不参与；没有元数据头部的文件不会被自动添加头部。`hexo clean` 和普通 `hexo server` 不写回日期。

写回只改变选定的日期行，保留其他元数据、注释、BOM、换行格式和正文；随后恢复写入前的文件修改时间，避免自动写入成为下一次更新的依据。Hexo 对受影响源文件重新处理，同一次生成中的首页最近更新、文章日期与目录使用新值。连续执行命令而没有编辑文件，不会重复改写 Markdown。

首次启用会同步既有文件中的旧日期。mtime 由当前文件系统提供，复制、解压、Git 重新检出或批量保存可能改变它；未来手动填写的日期保留到文件修改时间超过该日期时再同步。非法日期会报告文件路径并停止该次同步，不会重写其正文。

实现入口：`scripts/metadata-dates.js` 注册生成过滤器；`lib/metadata-dates.cjs` 处理日期、精确行替换、mtime 恢复和源缓存刷新。`tests/metadata-dates.test.cjs` 验证新建、后续修改、首次同步、已有缓存、同次生成和连续运行。
