# 网站视觉方案参考（Agent 指南）

适用范围：本站 Hexo Markdown 排版与共享阅读 UI。依据阴行世界多轮修改中确认的要求整理，更新于 2026-10-04。

本文约束设计判断和实现方式；具体章节数量、颜色、列数、分组与间距应依据内容和现有组件选择，不把单页定稿当成全站模板。用户当前的明确要求优先于本文。

## 1. 开始前先判断内容结构

阅读目标 Markdown，识别主章节、前置说明、同级问题、子条目、强调引用和具体内容，再决定容器。先解决层级与并列关系，再增加视觉装饰。

- 同级内容采用一致的标题级别、字号和间距；子条目必须在视觉上从属于上级。
- 前置说明与实际内容分组；长问题之间有边界；多个短问题尽量紧凑排列。
- 需要枚举时保留原有列表语义；长条目可用编号 UI，不能只突出小标题而让条目关系消失。
- 根据文本长度选择纵排或分栏；不要为了凑列数拆分同一段论述。

## 2. 必须保留的边界

- 保留原文措辞、信息、顺序、链接、媒体、元数据与交互功能。允许补充结构性小标题、分行和容器，不能擅自补写观点或删改正文。
- 优先修改 Markdown，让 Hexo 渲染可复用容器。不要在文章中写内联 CSS、`<style>` 或为单页复制一套样式。
- 需要新能力时修改共享标签、组件与设计变量；先确认现有能力不足，再扩展。
- 保留首页、总览、导览、故事、诗文等内容类型的阅读特点；统一基础规则不等于统一所有页面布局。

## 3. 组件选择依据

| 内容角色 | 优先选择 | 判断要点 |
| --- | --- | --- |
| 主章节 | Markdown 标题 + `content_section` | 形成章节层级；主题色服务于内容角色 |
| 前置说明、实际内容等分组 | `content_panel … group` | 用组标题组织内容，避免再套一个大框 |
| 并列问题或长说明 | `content_panel … plain`；需要边界时加 `separated` | 问题保持同级，分界不依赖重复的厚重卡片 |
| 具有多个长条目的说明 | `content_panel … plain steps` | 用子标题对应编号条目，编号在本组内连续 |
| 短问题、分类维度 | `content_panel … compact` | 缩小包围面积，保留列表与子标题层级 |
| 多个同级条目 | `content_grid rows` 或 `columns` | 长内容优先纵排；短内容可分栏，移动端应顺畅堆叠 |
| 需要整体圈定的一组内容 | `content_grid … framed` | 只圈定这一组；不要把外部说明也收入框中 |
| 独立信息、提示 | 既有 `note` / endnote | 保留其框状特征及语义颜色 |
| 需要强调的原文 | Markdown `>` | 使用全站强调引用样式，不另写特殊黄框 |

参数和闭合标签以 [额外 Markdown 样式使用说明](Hexo额外Markdown样式使用说明.md) 和当前实现为准。表中省略号表示主题参数，不是可以直接复制的语法。

## 4. 全站视觉规则

### 层级、密度与对齐

- 主标题、分组标题、同级问题标题、子枚举条目应有明确区别；不能把并列问题误排成上下级。
- 避免连续叠加“大标题框 + 小标题框 + 内容框”。优先用普通标题、分组、编号和留白表达关系。
- 标题型 note 保持既有框状设计。减少重复框体时，应调整内容组织和容器选择，不能直接取消 note 的特点。
- 标题、容器说明、编号和列表保持清晰的左对齐基线；自然段保留两字符首行缩进。引用、纯链接条目与 UI 文案按各自语义处理，不应统一强制缩进。
- Markdown 分割线表示视觉上断开的空白，沿用总览的共享规则；不绘制横线，也不叠加单页额外大间距。标题细线、问题边界和框体边线属于其他组件，不应混同。

### 颜色与强调

- 语义色应足够清晰，能够辨认角色与分组，不能只靠极淡背景区分。
- 相邻且角色不同的区域应避免主题色混淆；颜色由内容关系决定，不要求每个章节都换一种色。
- 使用共享明暗主题变量，保持文字可读性；不重新引入折角、叠纸等已被否定的装饰。
- 引用通常承载强调文本：沿用居中特殊字体、主题文字色与半透明底框，保持段落易读。

### 链接、按钮与弹窗

- 所有 Markdown 链接默认沿用加粗红体；悬浮和键盘焦点使用最近的主题容器的字体色与浅色背景，没有主题容器时使用默认主题。
- 规则必须覆盖嵌套容器、非 posts 页面及菜单阅读器；图片链接、导航和按钮保留各自组件语义。
- 按钮采用与网站纸面、边框和主题色协调的共享样式，避免突兀的亮黄大块或强烈装饰。
- 弹窗沿用共享纸面与主题色，保留原有内容、触发条件、关闭与其他交互行为。

## 5. 案例的正确使用方式

[阴行世界](../source/_posts/record/light/阴行世界.md) 用于理解选择逻辑，不作为固定模板：

- 众生回廊的前置说明和具体内容分组；Q1、Q2、Q3保持并列，内部条目另有编号或紧凑列表。
- Q2 的四组短问题采用统一细线框，体现它们属于同一组；框外论述仍独立。这不意味着所有问题或所有网格都必须加框。
- 众生回廊采用金色，是为了与蓝色信息栏区分；其他页面应根据自己的内容和相邻区域决定主题色。
- 异世之篇复用前置说明与具体内容的分组方法，条目数量、标题和布局仍由原文决定。

迁移时复用“内容角色 → 容器 → 视觉层级”的判断，不照搬章节名称、编号数量、颜色组合或列数。

## 6. 实现与验收

1. 确认当前源码及样式所有者，列出需要保留的内容和交互；不要用历史截图替代当前实现检查。
2. 先用现有 Markdown、Hexo 标签整理结构；只有公共能力缺失时才改共享样式或渲染逻辑。
3. 检查原文、链接、媒体和交互是否保留；确认新增标题准确，容器闭合，列表编号没有被重置。
4. 涉及渲染或样式时，检查桌面和移动端、明暗主题、悬浮与键盘焦点，重点看层级、密度、缩进、换行、溢出及嵌套容器的规则继承。
5. 全站规则变更应抽查不同阅读类型、非 posts 页面及菜单阅读器；页面结构变更检查对应页面。纯文档修改检查 Markdown 和本地链接即可。
6. 报告实际改动和已完成的验证。构建成功、截图或本地浏览不代表已经部署。
