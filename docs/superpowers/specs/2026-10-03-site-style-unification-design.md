# 全站视觉统一规划

日期：2026-10-03。状态：完成源码审查和页面基线，待确认设计后实施。

## 1. 目标与边界

以当前首页的黑白、金色、细边线、纸张层次和克制留白为全站共同语言。保留各部分基于内容形成的组织方式，通过 Hexo 渲染、共用样式和主题变量自动呈现一致的链接、按钮、提示块、分隔、强调与正文。

统一视觉规则与保留内容定制同时成立：首页继续是信封与三页信纸；总览继续是文明、子分类、文章的条框结构；木缘桑庭继续是时代时间轴、类型篇目索引、可展开解读和抉择点分栏；不同文章类型保留字体、阅读宽度、分行、缩进与信息密度的区别。

**用户补充的强制约束（2026-10-03）**：信封、滚动抽取信纸、收回信纸和对应展开动画仅用于首页 index。其他页面共享首页的精致、简约和视觉变量，不复制信封展开式 UI，不将普通文章、目录、分类、标签或分区页面变成信纸抽取交互。共享组件不能依赖首页展信脚本、inert 状态或滚动进度。

保留 Markdown 的特化性排版是硬性验收项。story 的衬线、缩进、较窄阅读栏和舒展行距，poetry 的原始诗行及段间节奏，lore 的条目等级与资料层次，essay 的自然段与分行，info 的紧凑信息布局，profile 的档案和人物图组都继续生效。不能通过统一所有正文的 font、line-height、text-indent 或段间距来取得表面一致。

**所有内容页的共同质量要求**：文章 Markdown、直接使用 `index.md` 的内容页、其他独立 Markdown 页面与已定制内容入口同步优化，不仅优化首页或几个代表页面。每页都要做到顶部必要信息完整、UI 协调、视觉丰富而不杂乱、排布整齐。以木缘桑庭现有优化中的信息层级、分区、条目对齐和内容密度为排布质量参照，同时保留各内容类型自己的阅读方式。

以下情况属于验收失败：同一层级或同一角色的字体无依据地忽大忽小；布局过挤；并列内容没有可辨边界；长页仅连续堆积文字而没有内容层级和分区；必要信息缺失；标题、控件或内容块排布不协调；不同部分的基础视觉语言差异过大。

此次不新增展示文案，不改正文、顺序、日期、分类、标签、标题锚点、链接目标、图片、视频、下载和原有脚本行为。不改远程发布配置，不推送或部署。当前未提交的修改均作为基线保留，只修改确实涉及统一规则的部分。

用户所说的 achieve 对应当前 `/archives/` 总览。现有源码的总览通过 section 和层级行展示，并没有原生 details 折叠；保留当前条框逐层展开的视觉组织，不凭空增加或删除折叠行为。文章和导览中实际存在的 details 保留原始展开状态及键盘行为。

`{% note %}…{% endnote %}` 中的 endnote 是 Hexo 提示块的闭合标签。此次统一提示块和折叠提示块，也覆盖首页页末附笺、文章版权与署名、导航页末说明；真实脚注如存在，采用低干扰的编号、细分隔线和可辨识的返回链接，不自动生成脚注。

## 3. 路线比较与选择

| 路线 | 收益 | 代价与问题 |
| --- | --- | --- |
| 提取设计变量与通用渲染组件，保留结构适配器（采用） | 每类元素有明确样式所有者；新文章自动一致；暗夜可系统验证 | 需要一次整理旧规则并逐类迁移 |
| 在现有样式末尾追加统一覆盖 | 短期改动少 | 会继续增加 specificity、important 和页面排除，未来容易重新分裂 |
| 将所有页面换成一个模板 | 实现直观 | 会损失信纸、条框目录、时间轴、诗行、人物图组等已有内容优化 |

采用第一条路线。工作顺序由共同规则向页面适配推进，最终以跨页面对照验收，不按首页、总览、文章逐页堆叠补丁。

## 4. 样式所有权与渲染架构

采用四层职责；导入顺序固定，后层仅负责自己的结构和明确变体：

1. **设计变量**：表面、文字、品牌金、边线、语义色、间距、圆角、阴影和动效时长，定义浅色与暗色。
2. **共用元素与组件**：正文、标题、文本链接、动作按钮、行式入口、提示块、折叠块、引用、表格、分隔、强调、附笺、焦点。
3. **阅读配置**：story、lore、essay、poetry、info、profile、guide，仅控制阅读宽度、字体、字号、行距、段落节奏和必要的资料布局。
4. **内容结构适配器**：首页信封/信纸、总览条框/层级、导览时代/分支、人物图组/档案、星图等；使用前两层共同变量，保留结构几何和内容语义。

不把全部旧样式保留后再追加第五层修补。删除或迁移已经有新所有者的旧声明；少数针对第三方内联样式的覆盖需写明来源和用途。

### 渲染方式

- 现有 `readingProfile`、`decorateReading`、`homepage`、`readingGuide` 和目录 helper 保留内容职责。
- 模板在通用链接/按钮/提示块等位置使用语义角色或共享类；自动渲染的 Markdown 元素直接进入共同规则。
- 写文章时继续使用 Markdown、note、details、现有类型字段，不要求段落增加页面专用 class、style 或主题色。
- `reading_style` 的显式选择和现有自动推断仍生效；`reading_tone`、`data-tone` 保留为内容辨识变量，不再改变整个页面的通用链接和正文颜色。
- 先识别组件职责，再选择规则：文本链接、动作按钮、内容入口、折叠开关、图片链接有各自通用模式。不能用一条全局 `a` 或 `button` 规则把所有角色压成相同形状。
- 不改变链接 href、标题 id、DOM 内容顺序、details 的 open 属性和脚本使用的 id。

## 5. 共同视觉规范

### 色彩和表面

首页 `#FFD700` 保留为品牌金，用于小面积强调、主按钮、焦点和细线。浅色正文使用中性深色，暗色正文使用中性浅色；浅色背景上的正文链接不使用低对比度的亮黄色字。

初始变量如下，实施中只允许通过同一变量整体校正，并根据最终实际表面验证对比度：

| 变量 | 浅色 | 暗色 |
| --- | --- | --- |
| `--world-gold` | `#ffd700` | `#ffd700` |
| `--world-paper` | `#fcfbf8` | `#1c1c1b` |
| `--world-surface` | `#ffffff` | `#242423` |
| `--world-ink` | `#242424` | `#ece9e2` |
| `--world-muted` | `#66645e` | `#aaa69c` |
| `--world-edge` | `#dcd8ce` | `#48453e` |
| `--world-gold-wash` | `rgba(255,215,0,.14)` | `rgba(255,215,0,.10)` |
| 主按钮文字 | `#171717` | `#171717` |

保留宇宙背景，降低其穿透阅读区的干扰。移除 main-inner、content-wrap、sidebar、popup 等祖先层的内容 opacity，以带 alpha 的背景表面表达透明感。保证文字、二维码、图标和焦点保持完整不透明。

内容区使用共同的纸张表面、细边框和轻阴影；首页封面保留黑金反差。首页信纸仍保留纸边、折角、页码、署名和层叠，暗夜变为低亮度的深色纸张，不能整页继续亮白。

### 类型颜色

文明、十二元素、三元、内容类型和 note 的 info/primary/success/warning/danger 保留必要的辨识色。限定在标签、小图标、类型标记和提示块窄侧线中，不同时给普通正文、链接、背景、分隔和按钮套上整页配色。

深色模式单独定义语义前景色与低饱和背景，不对原色机械反相。颜色之外继续保留标签文字与类型名称。

### 所有内容页的顶部信息区

顶部信息区是正文前的内容识别区域，不要求全站新增占据屏幕的固定工具栏。由 post、page 和定制布局共用信息模型与排布规则，避免文章有完整元信息而直接 `index.md` 页面只剩标题。

| 信息 | 呈现规则 |
| --- | --- |
| 页面标题 | 每页明确呈现一个主要内容标题；保持统一标题级别和视觉角色，长标题自然换行 |
| 内容类型与位置 | 使用现有 reading_style 标签、分类路径或所在分区，帮助读者理解当前内容及返回路径；不同时堆叠重复的路径与标签 |
| 作者或来源 | 原文明确提供作者、协作者或来源时展示；不将站点建设者默认冒充合作内容的作者 |
| 发布时间与更新时间 | 按原始 frontmatter 的真实字段和页面用途展示；无明确日期不将文件修改时间或 Hexo 推断时间充作发布日期；更新信息仅在有依据且有区别时展示 |
| 内容说明 | 原有 description 或既有说明存在时保留；不生成无依据的摘要来填满顶部栏 |
| 阅读或目录信息 | 长文章可保留已有阅读时长/字数；目录页展示真实计数与当前位置，资源页展示其用途和原有入口；不同用途不强行填同一套统计 |
| 导航与动作 | 同目录导航、原文入口、下载、类型索引等现有必要动作完整保留；主次分明，不挤在标题旁抢占阅读空间 |

标题、类型标记、路径、元信息与动作使用固定的角色层级和间距。桌面按清楚的行与列对齐，手机自然换行或纵向排列，保持有序阅读。信息有内容依据时必须呈现，字段不存在时不显示空标签、空白占位或伪造值。目录信息、作者/日期和小说正文中的虚构时代、人物资料分别表达，不能混为页面元信息。

当前 `page-header.njk` 主要呈现标题、说明和路径，`post-meta.njk` 则有日期、分类和统计；实施时需要统一其共同信息模型，保留两种布局实际需要的差异。不只给两套头部换颜色而继续留下信息缺口。

### 排布整齐与视觉丰富的共同规则

- **同层级同角色一致**：同组卡片标题、条目标题、元信息、按钮文字分别使用共同字号、字重和行高；主标题与副标题有明确差异。story 与 lore 的正文类型差异仍保留，同一正文类型不能因页面路径而随意变换字体。
- **建立稳定对齐线**：标题、正文、分隔与区块边界对齐；并列卡片使用共同网格、列间距和内边距。图标、标签、标题及尾部动作各有稳定位置，避免每个块各自排布。
- **并列内容可辨识**：独立并列块至少通过间隙与边界/表面区分；紧密相关的行通过轻细线区分。长短内容均完整展示，不用截断正文或强制缩小字体换取整齐。
- **密度适合内容**：设定和资料保持紧凑但不拥挤，故事保持连续阅读和舒展节奏，诗文保留诗行。长列表、字段和嵌套内容使用层级与适当分区，不堆成一整片无区分的文字。
- **视觉层次来自内容**：利用原有章节、note、列表、表格、引用、标签、媒体及资料字段，形成标题层、正文层、辅助层；以共同浅色块、细边线、少量语义色和留白丰富视觉。不能给每段加色块，或为了装饰增加图标、插图、标题与新文案。
- **正文分区自动渲染**：从 Markdown 已有结构识别章节、资料块和显式分隔，不要求逐页手工包裹样式。纯叙事正文保留连续性，通过章节、自然段与原有引述形成阅读节奏，不拆散诗节、列表或引用。
- **媒体协调**：封面、人物图、图注和嵌入内容与所属区块对齐，图组按内容维持统一网格；媒体不挤压元信息或与下一块重叠，保留原比例与必要内容。
- **响应式同样整齐**：手机端按相同信息优先级收为单列，标题/动作完整换行，并列块仍有分界；不以文字过小、间距过窄或隐藏必要信息解决拥挤。
- **明暗两套相同层级**：色块、细线、弱化文字和分界在暗夜也可辨识，不能只在浅色模式有结构、暗夜下退化成纯文字或粘连面板。

木缘桑庭的时间轴和分支布局是该页的内容组织；其他页面借鉴其清楚层级、规整对齐、可辨分组与完整信息的质量，不复制时间轴、抉择点或首页信封结构。

### 组件规则

| 组件 | 共同表现 | 保留的差异 |
| --- | --- | --- |
| 普通正文 | 中性色、清楚的层级和段落节奏 | 故事/诗文衬线；信息/设定无衬线；原始分行、缩进、阅读宽度 |
| 标题 | 中性色为主，细金线或小标记；去掉旧蓝紫渐变和重复装饰 | 时代编号、条目等级、信纸页码、设定资料标题的结构 |
| 文本链接 | 正文同系文字、持续可辨识的细下划线；浅金 hover 背景，键盘焦点明确 | 正文链接与标题/整行入口的密度不同；图片链接无文本高亮 |
| 主按钮 | 金底深字、6px 圆角、同一字重和内边距、轻量 hover/active | 首页主入口、原文按钮、弹窗确认复用；不改变文字或行为 |
| 次按钮与导航控制 | 中性表面和细边线，金色交互反馈 | 图标按钮和分页保持适合的紧凑尺寸 |
| 内容行/卡片入口 | 同一文字色、边线、箭头和 hover/focus 语言 | 总览行、资源卡片、文件夹入口和篇目索引保持各自布局 |
| note/endnote | 1px 中性边框、3px 语义侧线、8px 圆角、统一留白和正文色 | 五种语义色、标题-only 和混合正文、原始内容 |
| details/summary | 与 note/卡片一致的边线和表面，统一开关、focus 与展开分界 | 原始开闭状态、嵌套层级、类型标题 |
| 引用 | 中性浅/深表面、窄色线，正文可读；不用大面积紫色渐变 | 原文引述和署名 |
| 分割与分段 | 共同边线、短金色标记或留白；去掉互相冲突的 ◆、彩色渐变等 | 普通段落、章节、条框分组、时代之间使用不同级别的间距 |
| strong / em / mark | strong 靠字重与正文色强调；em 保留斜体；mark 用浅金衬底 | 仅确有重点的现有标记使用强调底线，避免每个粗体都染色 |
| 表格和代码 | 同一表面、边线、文字；表头低干扰；横向滚动仅在自身容器 | 数据结构、代码语法配色和复制/折叠行为 |
| 附笺和页末 | 小字号中性文字、细分隔，品牌只作小标记 | 首页双列署名、文章版权/赞赏/前后篇、目录说明各自内容 |

间距使用 4、8、12、16、24、32、48、64px 的共同阶梯。按钮圆角 6px、提示块 8px、一般资料卡片 10px；信封信纸保留约 2–3px 的纸张几何。正文段间距按 em，保留诗文较大间距。移动端减小容器留白，不通过过小字号压缩阅读。

### 统一分隔：让独立内容块在视觉上断开

分隔由内容关系决定，统一其层级和规则，不将全站所有间隔压成同一根线。

| 层级 | 适用内容 | 视觉规则 |
| --- | --- | --- |
| 连续正文 | 同一叙述中的自然段、诗行、同一条目的说明 | 保留类型原有段落节奏；不逐段拆卡，不增加装饰线 |
| 组内分隔 | 条框内文章行、资料字段、同一时代内条目、标签最近文章 | 1px 中性细线与 12–24px 组内间距；相邻边界只出现一次 |
| 章节分隔 | Markdown 原有 hr、独立章节、资料分组、note 与上下文 | 统一中性线和克制金色短标记，配合 24–32px 留白；清除旧菱形、三点和各自的彩色渐变 |
| 独立内容块断开 | 文明大分区、标签三大类型、四个记录分区、资源大组、导览时代与抉择点大块 | 以 24–48px 外部间隙、各自边界和独立表面形成可见断面；大块之间不再由连续背景、长边框或装饰线粘连 |

大块断开的主要手段是间隙和表面，不在每个块外增加厚重双线或反复金色框。间隙可露出低干扰的站点背景或共同中性底色，内层保留轻线和信息密度。暗夜下也必须能辨认断面，不能仅在浅色模式有间隙、暗色模式又粘成一片。

Markdown 使用已有 hr 和顶层章节关系识别分隔级别。需要渲染包装时只加不含新文本的语义容器，保留标题、段落和脚本的顺序、锚点及 link/media 属性；不能切开 note、details、列表、表格、引用或诗节。阅读配置里的直系子元素选择器随包装同步适配，保证故事缩进和诗文段距不丢失。短文没有章节时保持连续阅读，不强制拆卡。

首页信纸间的断开只是独立块分隔的一个特例。其他页面使用静态的独立内容区，不采用纸张抽取、叠放或滚动展开。

所有组件使用同一动效时长与曲线。保留首页原生滚动展信，通用控件仅有轻微背景、阴影和箭头变化；文本行不整体跳动。保留 `prefers-reduced-motion`、键盘和无 JavaScript 的正常阅读路径。

## 6. 暗夜状态与覆盖

使用明确的主题状态和 CSS 变量，而不是反色。由同一轻量主题脚本负责所有站内页面；在 head 中尽早确定状态，防止暗色访问时闪现白色阅读区。

- 继续读写现有 `localStorage.darkmode` 的 `true` / `false`，保留用户以前的选择。
- 没有手动选择时跟随系统配色；系统变化仍可更新。手动选择优先，刷新、跨页和同源独立页面保持一致。
- 存储不可用时仍可切换，不能因读取 localStorage 报错阻断网站。
- 保留右下方一个主题按钮，提供准确的 accessible name 和 `aria-pressed`，支持键盘操作。按钮位置不得遮挡返回顶部、移动端导航和正文。
- `html[data-world-theme]` 是统一 CSS 状态。`color-scheme`、浏览器 theme-color、滚动条和原生控件跟随。
- 替换 `hexo-next-darkmode` 的运行职责，移除它和不再使用的 `darkmode-js` 依赖并同步 `package-lock.json`，避免其无条件样式注入继续影响图片与 iframe。先以全库引用搜索确认无其他消费者；不修改 node_modules，也不升级其他依赖。
- 覆盖首页封面/信纸、总览/分类/标签/资源入口、七种阅读模式、note/details/quote/table/code、同目录导航、侧栏、搜索、分页、版权/赞赏、SweetAlert、二维码和评论组件。
- 图片、视频、二维码、图标和艺术色不反相、不机械降低 opacity。评论组件优先通过它已有的变量和主题接口适配。

## 8. 实施顺序与文件职责

每一步完成后回到共同组件样本检查，所有步骤最终合并为同一视觉系统。

1. **保存基线与功能清单**：记录当前 Markdown 正文 hash、元数据、锚点、媒体、脚本、details 状态和入口目标；保存当前已修改文件的副本。扩展现有保真检查，不把旧历史快照当作本次基线。
2. **建立双主题变量和主题生命周期**：增加 `source/_data/world-tokens.styl`、共用主题脚本与 head 接入；整理 NexT 与评论变量映射；替代暗夜插件，同步依赖锁文件。检查存储兼容、首屏、跨页、系统默认和存储不可用。
3. **提取通用组件**：增加 `source/_data/world-components.styl` 和 `world-prose.styl`；将 `interactions.styl` 收敛到通用角色的交互；整理 `styles.styl` 导入与旧规则。样式归属先完成，再迁移页面使用者。
4. **收敛阅读与渲染，并同步优化全部内容页**：`reading-profiles.styl` 仅留类型参数与类型资料布局；`lib/reading-profiles.cjs`、`scripts/reading-profiles.js` 和 post/page 模板只在需要时为共同元素补充语义类。统一 `page-header.njk`、`post-meta.njk` 与定制内容头部的信息模型及视觉角色，从真实原文与元数据补齐必要信息，按第 5 节校正每种正文类型的层级、对齐、密度与分区。将 `_macro/post.njk` 的青色内联页末署名改成共享 endnote 类，保留原文字。检查全部 `_posts`、直接 `index.md` 和其他独立 Markdown 内容页，而非只调整类型样例。
5. **迁移首页、目录和导览结构**：整理 `content-directory.styl`、`reading-layout.styl`、`home-refinement.styl`、`home-letter.styl`；保留几何、网格、时代与首页专属信纸动效，替换其重复的文字、颜色和通用组件声明；目录宏和阅读 helper 不改变内容提取结果。按第 7 节逐项检查 category/tag 的入口与结果、四个记录分区及对应原文，并按统一层级实现独立内容块的静态断开。
6. **覆盖完整外壳与特殊入口**：搜索、侧栏、评论、弹窗、二维码、原文按钮、rawhtml 工具栏改用共用规则。独立 HTML 加载相同轻量资产；若公共渲染注入资产，`scripts/redirect-pages.js` 的 server 旁路和 build 拷贝必须调用同一注入逻辑，禁止仅改 public 生成文件。
7. **回归与跨页面审阅**：清缓存重建，运行保真检查、既有交互检查和双主题检查；输出按组件和页面类别排列的对照截图；纠偏只改共同规则或确有内容依据的结构变体。
8. **维护文档**：更新 `MARKDOWN_READING.md` 和 `DIRECTORY_UI.md`，明确样式所有者、主题状态、阅读类型与语义色边界；记录检查结果和保留例外。

公共主题资产放在 `source/` 下，主主题与独立页面均加载它们，避免独立页面需要依赖 NexT 运行对象。NexT 主题特有的变量/外壳适配留在主题导入层；共同组件无需认识页面路径。

## 10. 设计自检与当前交付

该方案给每类共同元素一个样式所有者，给每类内容一个结构适配器，给明暗模式一个状态来源。各文章的阅读节奏、目录层级、首页艺术结构和时代分支均有明确保留项。普通界面颜色不再由文章类型决定，而内容语义颜色仍有适用范围。

已按此方案完成共享变量、公共组件、渲染装饰与各结构适配。用户后续提出的导航蓝灰反馈、逐自然段缩进、头部正文等宽、介绍块层级、加粗/代码和抽象主题按钮均纳入实现。验收范围与实际结果记录于实施计划；维护入口见根目录 `SITE_STYLE.md`。

后续内容定制继续落在渲染层：发行计划的阶段与参与步骤、协作者的身份卡与原始贡献折叠、协作方式、文件资源卡，以及关于的邀请/联系/赞赏均使用共同视觉变量。添加微信接入共用二维码弹窗，保留原图入口；原生 dialog 管理键盘焦点，二维码仍为源目录已有文件。管理资源不再把标题和说明分散到两端，手机端操作在同一内容列内换行。

深度复核将正文缩进与 UI 文案明确区分：每个自然段及旧式 `<br>` 文本行自动缩进两字，诗行、元数据、邀请、联系和资源说明不缩进。手动空白不与自动缩进叠加，原文仍保留。正文链接统一使用明暗适配的红色加粗与下划线；目录说明、标题、列表、路径与二维码按钮补齐纸面。路径归入顶栏，索引页也读取明确的源元数据。全量递归 Markdown 检查覆盖顶部和结尾，以实际首字位置、背景及截图作为验收证据。
